# BYRDocs 维基真题贡献

用这个 Skill 把 PDF、图片、回忆稿或已有页面整理成可阅读、可交互的维基真题，
或修改、补全并贡献已有试题。目标产物位于
`byrdocs/byrdocs-neowiki` 的 `exams/<试卷名>/index.mdx` 和同目录资源文件。

## 先区分两种“贡献”

| 用户目标 | 使用入口 |
| --- | --- |
| 搜索或下载主站资料、上传 PDF/ZIP、填写 archive metadata | `byrdocs` |
| 录入题目、修改维基页面、补答案、处理 MDX/题图、贡献 Neowiki PR | 本 Skill |

用户只说“贡献试题”且上下文不能判断时，只问类似：

> 你希望把原始试卷文件上传到 BYR Docs 资料库，还是把试题整理成可阅读的维基真题页面？

如果用户只想上传原始文件而不录题，停止本流程并转到 `byrdocs`。如果维基贡献需要
搜索、下载主站文件或确认来源 MD5，本 Skill 保持总流程所有权，按需使用 `byrdocs`
能力完成该子步骤。

## 执行门禁

以下门禁优先于后文示例和命令。不能满足时，保留已有产物并暂停，不用 draft PR、构建
通过或事后披露代替门禁。

1. **目标门禁**：先确定是新录入、修改、补答案、纠错、恢复 PR，还是主站原始文件贡献。
   目标含糊时只做不会改变状态的检查，然后询问用户。
2. **规则门禁**：开始编辑前完整读取 `references/contribution.md`，并按
   `references/upstream.md` 解析当前 `editing-guide`；提交前解析当前 `review-guide`。
   文档不可用时说明缺失的文档 ID 并暂停，不用 memory、旧快照或实现补全当前规范。
3. **来源门禁**：写入的题目、选项、分值、答案、学院、时间和来源必须能追溯到材料、
   当前规则或用户确认。来源残缺或互相冲突时保留不确定性，不自行选一个版本写成事实。
4. **资源门禁**：打开本次使用的每个题图和必要附件，核对可读性以及与题干、选项、答案
   的数值、文字和结构关系。无法查看或存在未解决冲突时先暂停；只有用户明确接受精确的
   未核验范围和风险，才可按 contribution reference 继续 draft PR。
5. **工具门禁**：不自动安装、升级或替换系统级、全局或项目依赖，不执行来源压缩包中的
   脚本、宏或可执行文件。缺少必要能力时说明缺口并询问用户。
6. **授权和范围门禁**：外部写入必须属于用户明确请求或已单独确认；commit、push、PR 前
   重新核对实际 diff、来源、不确定项和验证结果。询问确认后结束当前回复。

### 用户授权的范围

| 动作 | 处理方式 |
| --- | --- |
| 读取、查重、创建专用临时 checkout、生成本地页面、预览和验证 | 可直接执行 |
| 用户已明确要求的 commit、push、创建或更新 draft PR | 不逐步重复确认；目标或风险变化时重新确认 |
| 未明确要求的外部写入 | 说明动作、精确目标、影响和原因，只问一个确认问题并暂停 |
| 创建 fork、安装依赖、覆盖已有页面或远端分支、发布存在已知冲突或缺项的页面 | 始终单独确认 |
| force push、删除远端内容、扩大到其他试卷、标记 ready for review | 只有用户针对精确目标明确要求时才执行 |

“贡献试题”“继续处理”不自动授权主站和维基两条路径或所有外部写入。授权只适用于已说明
的动作、目标和范围；来源冲突、重复候选、远端状态变化或 diff 扩大时重新确认。非交互
环境无法取得必要确认时，报告 `CONFIRMATION_REQUIRED` 并停止目标动作。

### 内容和环境边界

- checkout 准备好后，按 contribution reference 的实时仓库索引读取任务对象；只有记录了
  文档缺口或出现实际校验失败时，才读取最小兜底实现，不泛读仓库或交叉验证已明确规则。
- 回忆题允许不完整和非原文表达，但必须如实保留不确定性；不把整页试卷照片当正文。
- 只使用当前项目支持的 MDX 组件和资源，不新增未经支持的 JSX、脚本、样式或远程资源。
- 不读取、展示或提交 token、cookie、校园网密码、GitHub access token、本机隐私路径或
  不必要个人信息；不把来源文件的二进制、base64 内容倾倒到回复、PR 或调试输出。
- 默认创建 draft PR。只有用户明确要求，才能标记 ready for review。

## 规则来源优先级

发生冲突时按以下顺序处理：

1. 按 `references/upstream.md` 解析的当前 Neowiki 官方编辑指南和仓库说明；
2. BYRDocs Blog 教程；
3. 仅在文档未覆盖时，当前 checkout 的 schema、相关实现和少量同类页面；
4. Agent 一般经验。

这不是默认的逐级交叉验证顺序：较高优先级来源已经回答当前问题时，不读取较低优先级
来源。模板、目标页面和验证命令仍是完成任务所需对象，不因本门禁而跳过。

schema 和 CI 是机器校验边界，不自动构成新的编辑规范。文档与实现或 CI 冲突时，不
静默用实现改写规则；保留验证结果，指出规则漂移，并让维护者或用户决定。

## 任务路由

### 新录入

从来源材料建立一个新试卷目录和 `index.mdx`。先查同一考试是否已有页面或 open PR，
再确认目录名、frontmatter、题目范围和资源。优先使用当前 checkout 的
`templates/exam-page.mdx`，不要从 Skill 复制另一份模板。

### 修改、补答案或纠错

先读取目标页面、相关资源、提交历史和用户提供的依据，只改能够核实的内容。答案或
解析有争议时说明依据和不确定性；不要为了填满页面而猜答案。

### 从回忆录题

清晰表达已知题意，不伪造精确原文、数字或选项。允许保留缺失题号、概述和明确的
占位信息。只根据实际答案覆盖情况填写 `答案完成度`。

### 恢复贡献或处理 PR

先查远端 open PR、真实 head、changed files、当前分支和目标试卷目录，从最靠后的可信
产物继续。更新同一 PR，不重复创建页面、分支或 PR。

## 阶段化工作流

| 阶段 | 进入下一阶段前必须具备 | 不满足时 |
| --- | --- | --- |
| 路由 | 任务类型、目标试卷、期望完成到本地还是 PR | 询问并暂停 |
| 准备 | 专用 checkout、最新 base、当前规则和仓库级指令 | 保留来源材料，不编辑 |
| 查重 | 已检查页面、目录、当前用户及其他贡献者的 open PR | 处理重复或让用户消歧 |
| 来源 | 已列出可验证事实、缺失项、冲突和所有必要资源 | 不把猜测写入页面 |
| 编辑 | 页面和资源只包含有依据的内容，未引入无关改动 | 回到来源或范围检查 |
| 内容审核 | frontmatter、题目、答案、公式和每个资源均已核对 | 不进入发布阶段 |
| 机器验证 | 当前仓库要求的 lint、check、build 和必要预览均有真实结果 | 报告失败，不用管道隐藏状态 |
| 发布 | 用户授权有效，diff 仅含目标试卷，branch/PR 状态已核对 | 询问或修复后再执行写入 |
| 收尾 | PR base/head/draft/files、CI 和 review 已按真实状态读取 | 如实报告未完成状态 |

每一阶段的恢复证据、具体检查和 GitHub 命令以 `references/contribution.md` 为准，不能
根据本表补造缺失步骤。

## BYRDocs CLI 边界

Neowiki 编辑、校验和 GitHub 操作不使用 `byrdocs wiki` 等不存在的命令。当前 CLI
只在需要主站搜索、下载或来源 MD5 时作为辅助；MDX 校验必须使用目标 Neowiki
checkout 自己的命令。

## 最终回复

- 给出创建或修改的试卷页面和仓库相对路径。
- 说明来源、已核实事实、仍不完整或不确定的内容。
- 报告 lint/check/build 的实际结果。
- 已创建或更新 PR 时给出 URL、draft/ready、CI 和 review 状态。
- 暂停时指出最靠后的持久化产物和需要用户决定的唯一下一步。
- 不倾倒长日志、完整 GitHub JSON 或任何敏感信息。
